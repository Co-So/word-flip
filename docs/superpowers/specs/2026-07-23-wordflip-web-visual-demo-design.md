# WordFlip Web 视觉演示版设计规格

> 状态：已完成会话设计确认，等待文档审核
> 日期：2026-07-23
> 适用目录：`wordflip-web/`
> 产品基线：WordFlip v7
> 契约基线：`wordflip-api/openapi.yaml`

## 1. 背景与目标

WordFlip 当前优先实现 Web 端，Android 端暂缓。第一阶段不直接联调全部后端接口，而是使用模拟数据完成一套可连续操作的视觉演示版；视觉、路由和业务交互确认后，再按功能模块逐步切换为真实 API。

本阶段的成功标准：

1. 所有主要页面均可访问，并形成完整的用户主流程。
2. 登录、首次设置、今日学习、翻卡、测验、统计和设置具备真实可点击交互。
3. 模拟数据跨页面一致，刷新后可继续演示。
4. 模拟行为遵守 v7 业务规则，不为视觉效果制造错误业务逻辑。
5. 页面不直接依赖模拟 JSON，后续可逐模块切换为真实 HTTP 数据源。
6. 1280px 以上桌面体验达到主要设计目标，窄屏保证功能可用。

## 2. 已确认的关键决策

| 决策项 | 结论 |
|---|---|
| 当前平台优先级 | Web 优先，Android 暂缓 |
| 第一阶段 | 视觉演示版，使用模拟数据 |
| 演示深度 | 完整可点击演示 |
| 页面状态 | 主流程 + 代表性空状态、错误状态和完成状态 |
| 页面结构 | 左侧导航的成熟桌面应用结构 |
| 视觉气质 | 暖米白纸张质感 + 鼠尾草绿 + 少量陶土橙 |
| Claude 借鉴范围 | 克制留白、清晰层级、工作台结构、等宽状态标签和快捷键表达 |
| 响应式策略 | 桌面端优先；窄屏保证可用 |
| 前端方案 | 功能模块化 + 可切换数据源 |
| API 接入策略 | 页面依赖稳定数据接口，逐模块将 `MockRepository` 替换为 `HttpRepository` |

## 3. 范围

### 3.1 本阶段包含

- 登录、注册和登录失败状态。
- 首次设置：词书、默认词典、每日数量和分组大小。
- 今日学习仪表盘。
- 词书列表、词书详情、词典选择和导入状态。
- 分组列表、分组详情和单词热力展示。
- 学习准备、翻卡学习和学习完成。
- 测验模式选择、听写测验、选择测验和结果页。
- 卡片图片上传、图片库和卡片外观页面。
- 学习统计与听写/选择双轨数据。
- 学习设置、外观设置和演示数据重置。
- 代表性加载、空数据、失败和成功状态。
- 模拟延迟、模拟失败和本地持久化。

### 3.2 本阶段不包含

- 生产身份认证和真实令牌刷新。
- 全量后端 API 联调。
- 服务端 SRS 计算、判题或导入解析在浏览器中的重新实现。
- 多设备实时同步。
- 推送提醒。
- Android 页面开发。
- 对每个页面穷举所有异常组合。
- 将 Claude Code 的布局、组件或品牌视觉原样复制。

## 4. 产品与设计原则

### 4.1 WordFlip 优先

Claude 风格只作为设计理念参考。WordFlip 保留自己的学习产品身份、Natural Sage 基础和单词卡片体验，不复制 Claude 的品牌标识、专有布局或文案。

### 4.2 安静但不松散

暖色背景和纸张表面负责营造长期学习氛围；清晰网格、稳定间距和明确状态负责保持效率。页面避免过度圆角、过多悬浮卡片和无意义装饰。

### 4.3 专注流程工具化

普通管理页面使用完整左侧导航。进入学习或测验后，侧栏收窄，中央展示当前单词或题目，右侧显示队列、进度和快捷键，形成克制的专注工作台。

### 4.4 业务真相不为演示让步

模拟层必须遵守产品基线：

- 翻卡和学习浏览不改变掌握度。
- 只有测验结果可以更新学习状态和稳定性。
- 听写和选择题按 skill 双轨维护。
- 设置词书时只为未入组单词增量追加分组。
- 取消词书不删除已入组单词。
- 一词一组。
- `wordKey = en.trim().toLowerCase()`。

## 5. 信息架构与路由

### 5.1 应用外壳

`AppShell` 包含：

- 左侧主导航。
- 顶部上下文栏、面包屑和全局搜索入口。
- 主内容区域。
- 用户和当前学习计划摘要。
- 全局反馈区域。

左侧主导航固定为五项：

1. 今日
2. 词书
3. 分组
4. 统计
5. 设置

学习、测验和媒体编辑作为上下文流程页面，不长期占用主导航位置。

### 5.2 建议路由

| 路由 | 页面 |
|---|---|
| `/` | 根据登录和首次设置状态重定向 |
| `/login` | 登录 |
| `/register` | 注册 |
| `/onboarding` | 首次设置 |
| `/today` | 今日学习 |
| `/books` | 词书列表 |
| `/books/:bookId` | 词书详情与词典选择 |
| `/groups` | 分组列表 |
| `/groups/:groupId` | 分组详情 |
| `/study/:sessionId` | 翻卡学习工作台 |
| `/study/:sessionId/complete` | 学习完成 |
| `/quiz` | 测验模式和范围选择 |
| `/quiz/:sessionId` | 听写或选择测验工作台 |
| `/quiz/:sessionId/result` | 测验结果 |
| `/media` | 卡片图片与外观 |
| `/stats` | 学习统计 |
| `/settings` | 设置与演示数据重置 |

未登录用户只能访问登录和注册页。已登录但未完成首次设置的用户进入 `/onboarding`。学习和测验路由必须存在有效模拟 session；无效 session 返回可恢复的状态页。

## 6. 前端架构

### 6.1 技术基线

- React 18
- TypeScript
- Vite
- 基于路由的页面拆分
- 功能模块化目录
- 可替换的数据仓储实现

具体依赖选择在实施计划中确定，本规格不锁定未必要的状态库或组件库。

### 6.2 建议目录边界

```text
wordflip-web/src/
  app/                 # 应用启动、路由、Provider、AppShell
  features/
    auth/
    onboarding/
    today/
    books/
    groups/
    study/
    quiz/
    media/
    stats/
    settings/
  components/          # 跨功能通用 UI
  design-system/       # Web tokens、基础组件和动效规范
  data/
    contracts/         # Repository 接口与统一错误
    mock/              # 固定种子、模拟仓储、场景控制
    http/              # 后续真实 API 实现
    mappers/           # OpenAPI DTO 与页面模型转换
  domain/              # 客户端展示所需的稳定领域模型
  test/                # 测试工具、固定数据和场景构建器
```

每个功能模块只负责自身页面、交互和展示模型。跨模块业务通过明确的 Repository 接口协作，禁止页面直接读取其他模块的内部状态。

### 6.3 数据接口

首版至少定义下列边界：

- `AuthRepository`
- `SettingsRepository`
- `BookRepository`
- `GroupRepository`
- `TodayRepository`
- `StudyRepository`
- `QuizRepository`
- `MediaRepository`
- `StatsRepository`

页面只依赖这些接口。运行时通过统一装配选择 `MockRepository` 或 `HttpRepository`。允许按模块切换，例如登录已接真实 API，而学习和测验仍使用模拟实现。

OpenAPI DTO 不直接成为页面状态。`data/mappers` 负责把服务端字段转换为稳定的领域模型，避免接口字段变化扩散到组件树。

模拟实现只负责回放预先定义的服务端响应和演示状态变化，不在浏览器中实现 SRS 间隔、判题、导入解析或今日任务计数算法。切换到 `HttpRepository` 后，学习状态、测验结果、分组增量和今日计数全部以服务端响应为准。

## 7. 模拟数据设计

### 7.1 固定种子

默认演示账户使用固定种子，确保每次重置后都得到相同数据：

- 当前日期：固定为 2026-07-23，UI 明确标识模拟模式。
- 连续学习：7 天。
- 已掌握：126 词。
- 待复习：18 词。
- 今日完成度：72%。
- 最近学习：雅思核心词汇，第 12 组。
- 今日任务：新词 20、到期复习 18、测验 12。

固定种子只用于演示稳定性，不应散落在页面组件内。

### 7.2 本地持久化

模拟状态写入版本化的浏览器本地存储。状态至少包含：

- 登录与首次设置状态。
- 已选词书和默认词典。
- 已生成分组。
- 学习 session 和浏览进度。
- 听写/选择双轨测验结果。
- 今日任务完成量。
- 统计汇总。
- 图片元数据和卡片外观选择。
- 演示数据 schema 版本。

schema 版本不兼容时执行明确迁移或重置，禁止静默产生半旧半新的状态。

### 7.3 场景控制

模拟层支持稳定触发：

- 正常主流程。
- 登录失败。
- 今日无任务。
- 空词书。
- 空分组。
- 请求加载。
- 保存失败与重试。
- 测验完成。

场景控制只在开发和视觉演示环境可见，真实生产模式不展示。

## 8. 核心交互

### 8.1 登录与首次设置

演示账号可正常登录。登录页允许触发一次失败状态，错误文案不说明账号是否存在。

首次设置依次完成词书、默认词典、每日数量和分组大小选择。保存后生成初始分组并进入今日页。

### 8.2 今日任务

今日页聚合任务和最近学习，但不自行计算业务真相。用户可进入：

- 新词学习。
- 到期复习。
- 听写或选择测验。
- 上一次未完成的学习 session。

完成流程后，所有页面读取同一份演示状态，今日数量和统计同步变化。

### 8.3 翻卡学习

支持：

- 点击或空格键翻面。
- 方向键切换上一词/下一词。
- 查看发音、释义、例句、图片和当前热力。
- 暂停并恢复 session。

学习完成只写入浏览进度和 session 结果，不更新三态或稳定性。

### 8.4 测验

测验包含听写和选择两种 skill。提交答案后，`MockQuizRepository` 从固定场景中取得预先计算的服务端结果，再通过演示状态的统一入口 `applyQuizResult` 写入对应 skill 的结果、热力、稳定性和统计。浏览器不实现真实判题或 SRS 算法。

页面禁止直接修改掌握度。切换到真实 API 后，`HttpQuizRepository` 只提交答案并接收服务端结果，不在本地调用状态算法。结果页必须说明变化来自本次测验，而不是来自翻卡行为。

### 8.5 词书与分组

设置新增词书时，只为尚未入组的单词追加分组。取消勾选不撤回已入组单词，不删除已有分组。组详情以热力为主展示，并允许进入学习或测验。

### 8.6 设置与重置

设置保存后影响后续模拟任务。重置演示数据需要二次确认，执行后恢复固定种子并返回今日页。

## 9. 视觉系统

### 9.1 视觉方向

页面采用：

- 成熟桌面应用结构。
- 暖米白画布和纸张感表面。
- Natural Sage 学习语义。
- 少量陶土橙用于专注入口和关键强调。
- 等宽字体用于状态、进度、快捷键和开发式信息。
- 衬线字体用于少量大标题，正文与控件使用清晰无衬线字体。

Claude Code 的借鉴限于信息层级和工作台理念，不复制其组件外形、品牌或产品结构。

### 9.2 Web 主题建议值

| Token | 建议值 | 用途 |
|---|---|---|
| `canvas` | `#F8F5EF` | 主画布 |
| `sidebar` | `#EEE9DF` | 左侧导航 |
| `surface` | `#FDFBF7` | 卡片和输入表面 |
| `border` | `#DED7CB` | 默认边框 |
| `text-primary` | `#302D29` | 主文本 |
| `text-muted` | `#7F776C` | 次文本 |
| `learning-sage` | `#6F9038` | 学习进度、成功和选中 |
| `learning-sage-container` | `#B7D07A` | 轻强调容器 |
| `focus-terracotta` | `#C76A49` | 专注入口和少量关键 CTA |

以上是 Web 专属扩展。Android 继续遵守现有 Natural Sage 主题，除非后续另行批准跨端统一。

### 9.3 组件与密度

- 常规面板圆角 12px，小型控件圆角 8px。
- 主要容器使用 1px 低对比边框，阴影只用于浮层或必要层级。
- 左侧导航约 200–224px，可在窄屏收窄。
- 页面内容采用稳定网格，不使用大量自由漂浮卡片。
- 主按钮数量受控，每个视图只保留一个明确主动作。
- Material Symbols Outlined 用于结构图标，不使用 emoji 充当导航图标。

### 9.4 动效

- 翻卡是核心物理动效，默认时长 360ms，保持可中断、可预测。
- 页面和面板反馈使用 160–220ms 淡入或 4–8px 位移，不做大幅飞入。
- 任务完成、状态更新使用局部反馈，不触发全屏庆祝。
- 支持 `prefers-reduced-motion`，减少动态模式下保留状态反馈但移除不必要位移。

## 10. 响应式

主要验收宽度为 1440px 和 1280px。

窄屏策略：

- 左侧导航收窄为图标栏或可展开抽屉。
- 主内容保持单列优先。
- 学习/测验右侧状态栏可折叠到下方。
- 表格允许转换为列表或分段展示。
- 禁止出现页面级横向滚动。

首版不追求手机 Web 的像素级精细设计，但核心流程必须可完成。

## 11. 状态与错误处理

### 11.1 代表性状态

- 登录失败：表单内提示，不清空用户输入。
- 今日无任务：展示完成反馈和浏览词书入口。
- 空词书/空分组：说明原因和下一步。
- 测验完成：展示听写/选择双轨结果和状态变化来源。
- 加载：使用稳定骨架屏，避免布局跳动。
- 保存成功：轻量提示并同步更新页面。
- 保存失败：保留输入，说明可重试动作。
- 无效 session：提供返回今日页或重新开始的恢复路径。

### 11.2 统一错误模型

模拟层和 HTTP 层共享统一错误模型，至少区分：

- 校验错误。
- 未认证或会话失效。
- 资源不存在。
- 冲突。
- 网络或服务暂不可用。
- 未知错误。

页面不得依赖模拟层专属错误字符串。接入真实 API 时只替换错误映射，不重写页面反馈逻辑。

## 12. 无障碍与键盘

- 所有主要交互可通过键盘完成。
- 焦点样式清晰可见。
- 翻卡不能只依赖鼠标悬停。
- 颜色不是区分热力或正确性的唯一方式。
- 表单错误与具体字段建立关联。
- 弹窗和抽屉正确管理焦点。
- 常规文本和关键控件达到 WCAG 2.1 AA 对比度要求。
- 尊重系统减少动态效果设置。

建议快捷键：

| 操作 | 快捷键 |
|---|---|
| 全局搜索/命令入口 | `Ctrl/⌘ + K` |
| 翻卡 | `Space` |
| 上一词/下一词 | `←` / `→` |
| 提交测验答案 | `Enter` |
| 退出专注工作台 | `Esc` |

快捷键不能阻止标准浏览器或输入框行为。

## 13. 测试与验收

### 13.1 单元测试

必须覆盖：

- 学习浏览不改变掌握度。
- `applyQuizResult` 是模拟层唯一掌握度更新入口。
- 听写/选择双轨互不覆盖。
- 分组只增量追加。
- 取消词书不删除已入组单词。
- 演示数据重置恢复固定种子。
- 本地状态 schema 版本处理。

### 13.2 组件测试

覆盖：

- 登录和首次设置表单校验。
- 翻卡与键盘操作。
- 测验作答、提交和结果展示。
- 代表性空状态与失败重试。
- 设置保存和重置确认。

### 13.3 端到端测试

至少覆盖：

```text
登录
→ 首次设置
→ 今日页
→ 翻卡学习
→ 完成测验
→ 统计变化
→ 刷新后状态仍存在
→ 重置演示数据
```

### 13.4 视觉与响应式检查

- 1440px：完整桌面布局。
- 1280px：主要验收布局。
- 1024px 或更窄：导航收起、内容无横向溢出。
- 学习和测验专注工作台单独检查。
- 主要空状态、错误状态和结果页纳入截图检查。

## 14. 真实 API 迁移

API 接入按模块推进：

1. 身份认证。
2. 设置、词书和词典。
3. 今日任务与分组。
4. 学习 session。
5. 测验与结果更新。
6. 统计。
7. 图片与媒体。

每个模块迁移步骤：

1. 对照 `wordflip-api/openapi.yaml` 建立 DTO。
2. 在 `data/mappers` 转换为现有领域模型。
3. 实现对应 `HttpRepository`。
4. 运行同一组契约测试。
5. 切换该模块的数据源。
6. 保留模拟实现用于演示、离线开发和稳定测试。

页面、视觉组件和路由不因切换数据源而重写。

## 15. 文档同步要求

本规格审核通过并进入实施时，需要同步：

- `TASK.md`：将 Web 视觉演示版设为当前实施主线，并拆分任务。
